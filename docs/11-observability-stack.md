# Observability Stack

This phase adds a modern Kubernetes observability stack to the Talos homelab.

## Stack

```text
Metrics:
node-exporter + kube-state-metrics + Kubernetes targets
        ↓
Prometheus
        ↓
Grafana

Logs:
Kubernetes pod logs
        ↓
Grafana Alloy
        ↓
Loki
        ↓
Grafana

Alerts:
Prometheus alert rules
        ↓
Alertmanager
```

Installed components:

- `kube-prometheus-stack` — Prometheus, Grafana, Alertmanager, Prometheus Operator, node-exporter, kube-state-metrics
- `loki` — log storage and query backend
- `alloy` — modern Grafana collector/agent for Kubernetes logs

## Prometheus / Grafana / Alertmanager

`kube-prometheus-stack` provides the metrics foundation.

Prometheus scrapes metrics from Kubernetes components and exporters. Grafana visualizes those metrics. Alertmanager receives alerts generated by Prometheus rules.

Important pieces:

- **Prometheus** — metrics database and query engine
- **Grafana** — dashboards and Explore UI
- **Alertmanager** — alert routing
- **node-exporter** — host/node metrics
- **kube-state-metrics** — Kubernetes object state metrics
- **Prometheus Operator** — manages Prometheus CRDs such as `ServiceMonitor`

Grafana is exposed privately over Tailscale, not publicly:

```text
https://grafana.tail2be9f6.ts.net
```

Local port-forward access still works as a fallback:

```bash
kubectl -n monitoring port-forward svc/monitoring-grafana 3000:80
```

Then open:

```text
http://localhost:3000
```

Initial credentials:

```text
admin / admin
```

This is acceptable for first boot only. Replace this with a proper secret before treating Grafana as production-like.

## Pod Security Lesson

Node Exporter initially did not create a pod because it needs host-level access:

```text
hostNetwork
hostPID
hostPath mounts
hostPort 9100
```

The `monitoring` namespace needed to allow privileged infrastructure agents:

```bash
kubectl label namespace monitoring \
  pod-security.kubernetes.io/enforce=privileged \
  pod-security.kubernetes.io/audit=privileged \
  pod-security.kubernetes.io/warn=privileged \
  --overwrite
```

This should stay scoped to infrastructure namespaces. Do not weaken Pod Security globally.

Rule of thumb:

```text
normal apps       -> restricted/baseline namespace
node-level agents -> privileged infrastructure namespace
```

## Loki

Loki stores and queries logs. It does not collect logs by itself.

For this single-node learning setup, Loki runs in `SingleBinary` mode with filesystem storage and persistence disabled.

Important tradeoff:

```text
Loki pod restart -> stored Loki logs may be lost
```

That is fine while learning the stack. Before relying on Loki for production-grade incident response, add real storage and backups.

Loki uses writable paths under `/tmp/loki` because persistence is disabled and the container filesystem is read-only.

Grafana Loki data source URL:

```text
http://loki-gateway.monitoring.svc.cluster.local
```

Debug Loki:

```bash
kubectl -n monitoring get pods | grep loki
kubectl -n monitoring logs loki-0 -c loki --tail=100
kubectl -n monitoring get svc | grep loki
```

## Grafana Alloy

Alloy collects Kubernetes pod logs and sends them to Loki.

The current pipeline is:

```text
discovery.kubernetes "pods"
        ↓
discovery.relabel "pod_logs"
        ↓
loki.source.kubernetes "pod_logs"
        ↓
loki.write "default"
        ↓
Loki gateway
```

The labels added to logs are:

- `namespace`
- `pod`
- `container`
- `node`

Debug Alloy:

```bash
kubectl -n monitoring get pods | grep alloy
kubectl -n monitoring logs -l app.kubernetes.io/name=alloy --all-containers --tail=100
```


## Custom Homelab Alerts

The first custom Prometheus rules are stored in Git at:

```text
manifests/monitoring/homelab-alerts.yaml
```

Current custom alerts:

- `PodRestartingFrequently` — warning when a pod restarts more than 3 times in 15 minutes.
- `NginxSitePodDown` — critical when the nginx deployment serving `danieljcheung.com` has no available replicas for 2 minutes.

Apply or update the rules with:

```bash
kubectl apply -f manifests/monitoring/homelab-alerts.yaml
kubectl -n monitoring get prometheusrule homelab-alerts
```

Grafana Alerting is the preferred notification path for now. Alertmanager receives the Prometheus alerts, and Grafana can be used to configure contact points and notification policies through the private Tailscale UI.

A draft public-site probe alert exists locally only if blackbox-exporter is added later. Do not rely on `probe_success` rules until blackbox-exporter is installed and scraping `danieljcheung.com`.

## Current Limitations

This is a strong learning-grade observability stack, but not production-grade yet.

Known gaps:

- Grafana password is still simple/initial
- Grafana is now exposed privately over Tailscale; the admin password still needs hardening
- Loki persistence is disabled
- no backup/restore workflow for observability data
- notification policies/contact points still need to be finalized in Grafana Alerting
- control-plane metrics for Talos etcd/controller-manager/scheduler are disabled for now
- monitoring is installed by Helm commands, not fully managed by Argo CD yet
